# Приложение D. Глоссарий

Термины ниже употребляются в книге в особом смысле. Каждая статья указывает
раздел, где термин объяснён. Сначала идут термины на русском языке, затем — те,
которые книга пишет только как код или английское слово.

**анонимное действие** (anonymous action) — действие, написанное на месте
как значение: `(value is int) is int { value * 2; }`. Оно захватывает
значения, а не переменные, и не может быть async (§18.1).

**асинхронное действие** (async action) — действие, объявленное `async`. Его
вызов возвращает `Future<T>`, и только асинхронное действие может выполнять
`await` (§20.1).

**асинхронный destroy** (`async destroy`) — блок `destroy`, которому разрешён
`await`. Область, владеющая объектом, дожидается его при закрытии, и отмена
его не прерывает (§11.8).

**вариадический параметр** (variadic parameter) — последний параметр
`values is ...T`, который принимает ноль или больше позиционных аргументов.
Распаковывается записью `values...` (§13.4).

**верхний тип `any`** (any) — значение, попавшее в `any`, становится
непрозрачной коробкой: его можно хранить и передавать дальше, но нельзя
сузить обратно (§4.6).

**владелец** (owner) — область, которая уничтожает объект, когда
заканчивается. Связывание владеет переданным ему новым объектом, а
возвращённый объект переходит к вызывающему (§11.5).

**владелец состояния** (state owner) — задача, которая держит состояние в
локальной привязке и меняет его по сообщениям, которые другие задачи
присылают через канал (§20.6).

**встроенное действие** (builtin action) — действие встроенного значения
(`int`, `string`, массивов, словарей, `Future`), которому не нужен импорт,
например `size()` или `length()` (приложение B).

**группа native** (native group) — одна из групп нативов (`Fs`, `Net`,
`Process`, `Env`, `Clock`, `Random`, `Terminal`), которую может запретить
приложение, встраивающее среду исполнения (§21.6).

**действие** (action) — именованная часть поведения объекта с
типизированными параметрами и объявленным результатом (`is T` или
`is void`). Свободных функций в Okkama нет: каждое действие принадлежит
объекту, кроме `main` модуля (§13.1).

**задача** (task) — единица конкурентности внутри одного запуска. Один
планировщик выполняет одну задачу за раз и переключается только на `await`
(§20.3).

**заимствование** (borrow) — второе имя или параметр, указывающие на объект,
которым владеет другая область. Заимствование никогда не уничтожает объект
(§11.5).

**запасное значение** (`else`, fallback) — `value else fallback`: ответ на
случай, когда `Maybe` равен `none` или индекса либо ключа нет (§7.5).

**канал** (channel) — ограниченная очередь FIFO `Channel<T>` из
`async/channel`. Работа с ней идёт через концы `Sending<T>` и `Receiving<T>`
(§20.6).

**компактный `if`** (compact if) — однострочный `if`,
`if condition: a else: b`: выражение, обе ветки которого — одиночные
выражения (§9.4).

**константа модуля** (`const`) — значение, которое вычисляет компилятор из
литералов, других констант и операторов. Константа публична, если не
помечена `hidden` (§19.6).

**конструктор** (constructor) — способ создать объект. Каждый объект
объявляет хотя бы один конструктор: полный, с параметрами и телом, или
сокращённый `Name(:field)` (§12.3, §12.4).

**короткая ветка** (compact case) — ветка `match`, записанная одной строкой:
`case образец: значение;` (§16.4).

**модуль** (module) — один исходный файл, который начинается с
`module name vX.Y.Z;`. Модуль может занимать несколько файлов, перечисленных
вместе (§19.1).

**натив** (native) — функция, которую предоставляет хост, а модуль объявляет
словом `native` без тела. Это единственный путь за пределы программы (§21.1).

**нативный объект** (native object) — тип-дескриптор, например файла или
сокета, который может создать только натив. Программа хранит его и передаёт
обратно нативам (§21.3).

**номинальный** (nominal) — определяемый именем и объявлением, а не формой.
Типы номинальны (§4.4), и объект выполняет роль, только объявив `does`
(§14.2).

**область** (scope) — блок, итерация цикла или ветка. Область владеет тем,
что создаёт, и освобождает это при завершении (§11.5).

**обобщённый параметр** (generic parameter) — параметр типа объекта, роли или
перечисления, например `T` в `Box<T>`. Выводится при конструировании (§17.1).

**объект** (object) — единственное место для поведения: приватные поля,
явные конструкторы и действия, без наследования (§12.1).

**объект-значение** (value object) — объект, все поля которого — скаляры,
перечисления или другие объекты-значения, без `destroy` и без cap. Он
сравнивается по полям и может быть ключом словаря (§12.9).

**остановка по бюджету** (budget stop) — конец запуска, потому что исчерпан
бюджет шагов, памяти, вывода или времени. Её нельзя перехватить, и это не
отказ программы (§10.13).

**ошибка исполнения** (runtime error) — дефект, найденный во время работы,
например индекс вне диапазона или непривязанное поле. Её нельзя перехватить,
и она завершает запуск после очистки (§10.4).

**пакет** (package) — git-репозиторий, версии которого — его теги `vX.Y.Z`, а
модули лежат в `src/`. blade устанавливает пакеты в `pkg/` (§19.7).

**параметр-ключ** (key parameter) — обобщённый параметр, используемый как ключ
словаря. Каждая специализация должна давать ему тип, который может быть
ключом (§17.5).

**перепривязка** (rebind) — `name = expr;` без `let`: перевод локальной
привязки на преемника её объекта. Допустима только для типов с действиями-
преемниками (§13.7).

**перечисление** (enum) — закрытый набор именованных вариантов,
`enum Priority = (low, normal, urgent);`. Вариант может нести поля данных
(§16.1, §16.2).

**перечисление ошибок** (error enum) — перечисление, объявленное `is Error`.
Как типизированные отказы бросаются и перехватываются только перечисления
ошибок (§10.5).

**поле** (field) — состояние, объявленное словом `has`, например
`has given, family is string;`. Поле приватно для своего объекта и не
меняется после конструирования (§12.2).

**полномочия** (authority) — то, чего код может касаться за пределами
программы: файлы, часы, окружение, другие процессы. Стандартная библиотека
передаёт их значениями: `DirectoryLocating`, `Timing`, снимок `Environment`
(§21.4).

**правило must-use** (must-use rule) — результат действия-преемника обязан
быть использован: возвращён, передан, сохранён, использован как получатель
вызова или перепривязан (§13.6).

**преемник** (successor, `is ^T`) — действие, возвращающее новый объект:
поля, подготовленные записью `^field = value`, заменяются, остальные
копируются из получателя (§13.5).

**пример в документации** (doc example) — пример кода в огороженном блоке
doc-комментария. `okkama run -t` компилирует его, а пример с пометкой
`okkama,run` ещё и выполняет (§15.9).

**принятие во владение** (adopt) — то, что вызванное действие делает с новым
аргументом, которым ещё никто не владеет: становится его владельцем и
уничтожает его при возврате, если не вернёт (§11.5).

**процесс-воркер** (process worker) — синхронное действие, запущенное через
`spawn`. Оно выполняется в отдельном процессе, и через границу проходят
только скаляры, массивы и словари (§20.4, §21.5.1).

**путь модуля** (module path) — имя модуля через косую черту, `shop/money`, и
путь, по которому он импортируется: `import "shop/money"` (§19.1, §19.3).

**путь `std.`** (std. path) — объявление стандартной библиотеки, названное на
месте без импорта, например `std.io.stdout.Stdout()` (§19.2).

**роль** (role) — номинальный контракт из сигнатур действий, без полей и
тел. Объекты выполняют роль, объявляя `does` (§14.1).

**роль оператора** (operator role) — стандартная роль, например
`Adding<T, R>`, которая даёт объекту оператор: `a + b` означает `a.plus(b)`
(§14.7).

**связанное действие** (bound action) — действие объекта, взятое как значение
без вызова: `retail.of`. Оно несёт свой получатель и существует только там,
где записан его тип действия (§18.5).

**скрытый** (`hidden`) — не входящий в публичный контракт. Скрытые объект,
роль, перечисление или константа остаются внутри модуля (§19.5), скрытое
действие — внутри объекта (§12.7).

**специализация** (specialization) — обобщённый тип с аргументами, например
`Box<int>`. Каждая специализация — отдельный тип, без вариантности (§17.6).

**ссылка через роль** (role reference) — значение, типизированное ролью.
Через него доступны только действия роли, и ничто не превращает его обратно в
объект (§14.3).

**структурный await** (structured await) — правило: отмена задачи отменяет
future, которого она ждёт, если сама его запустила, и дожидается его
очистки (§20.5).

**тест** (test) — блок `test "name" { … }` рядом с кодом, который он
проверяет; выполняется командой `okkama run -t`. Внутри теста привязка
`test` даёт проверки (§15.1, §15.2).

**тип действия** (action type) — тип значения-действия, записанный как его
сигнатура без имён: `(int, int) is int`, или `async (int) is string` для
асинхронного (§18.1).

**фейк** (fake) — реализация роли только для тестов. Пишется внутри роли и
создаётся через `Role.fake()` (§15.3).

**функциональный блок** (functional block) — блок после `map`, `filter`,
`reduce`, `any`, `all` или `find`: `xs.map() -> x { x * 2; }` (§8.2).

**ячейка** (`Cell`) — `Cell<T>` из модуля `cell`, единственный изменяемый
контейнер для синхронного кода. Ячейка не может быть полем и не может
использоваться в асинхронном коде (§13.11).

## Термины, записываемые как код

**`Atomic`** — `Atomic<T>` из `async/atomic`: одно значение, которое задачи
разделяют и заменяют целиком; для координации есть `compare_and_replace`
(§20.8).

**`await`** — унарный оператор, который ждёт future внутри асинхронного
действия. Он возвращает значение future или заново бросает его отказ (§20.1).

**blade** — инструмент пакетов Okkama. Добавляет, синхронизирует и обновляет
зависимости из git и выбирает наименьшую версию, удовлетворяющую всем
манифестам (§19.7).

**`Cancelled`** — встроенный отказ, который бросает `await` для future, чья
отмена завершилась (§20.5).

**cap** — именованный контракт вычисляемых полей, который предоставляет
объект: вид только для чтения. Берётся записью `object::Cap`, читается
записью `card::field` (§12.8).

**`confirm`** — инструкция проверки условия. Без `else` ложное условие
вызывает panic, а с `else throw …` бросается типизированная ошибка (§10.9).

**`defer`** — выражение, зарегистрированное на конец области. Выполняется в
обратном порядке регистрации, до уничтожения объектов области (§11.3).

**`destroy`** — блок очистки объекта. Выполняется, когда заканчивается
область, владеющая объектом, на любом пути выхода из неё (§11.4).

**`does`** — слово в заголовке объекта, объявляющее роли, которые объект
выполняет: `object Bottle does Package` (§14.1).

**`for await`** — цикл по асинхронному источнику: каждый проход ждёт
`next()` источника (§20.10).

**`Future`** — `Future<T>`, значение, которое возвращает асинхронный вызов.
Ленив, выполняется не больше одного раза и хранит исход; значение достаётся
только через `await` (§20.1).

**`match`** — выражение, разбирающее значение по вариантам, с блочными или
короткими ветками и проверяемым остатком (§16.3).

**`Maybe`** — `Maybe<T>`, значение или его отсутствие: `Maybe.some(value)` или
`Maybe.none` (§7.3).

**`once let`** — привязка, вычисляемая один раз на объект при первом
обращении и сохраняемая для этого объекта (§13.13).

**`panic`** — отказ, сообщающий о нарушенном инварианте. Его нельзя
перехватить, и он завершает запуск после очистки (§10.4).

**`Presence`** — `Presence<T>`, добавляет `missing` к `some` и `none` для
обновлений, где «оставить» и «очистить» различаются (§7.7).

**`spawn`** — оператор, запускающий вызов сейчас: асинхронное действие
становится задачей запуска, синхронное — процессом-воркером (§20.4).

**`test.case`** — именованный подслучай внутри теста,
`test.case(name) { … }`. О его отказах сообщается отдельно, и фильтр может
выбрать его (§15.9).

**`test.throws`** — `test.throws(Type) { … }` требует, чтобы блок бросил
`Type`, и возвращает перехваченную ошибку (§15.2).

**`throw`** — инструкция, бросающая значение перечисления ошибок. Голый
`throw;` в `catch` бросает ошибку заново (§10.6).

**`try?` и `try!`** — пометки, превращающие типизированный отказ вызова в
`Maybe` (`try?`) или в panic (`try!`) (§10.10).

**typestate** — протокол, записанный как одна роль на состояние; каждый
переход возвращает роль следующего состояния (§14.5).

**`void`** — маркер действия, которое не возвращает значения. Это не тип
(§13.1).
