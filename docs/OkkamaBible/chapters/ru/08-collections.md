# Глава 8. Коллекции

В Okkama три встроенные коллекции — массивы, словари и диапазоны, — а
стандартная библиотека добавляет поверх них списки, множества, деки, кучи и
ленивые представления. Все они неизменяемы. Этот единственный факт решает
большую часть главы: как коллекции строятся, как меняются, сколько стоят и
чего пока не хватает.

## 8.1 Массивы

Массив — неизменяемая упорядоченная последовательность значений одного типа,
записываемая `@T`. Литералы пишутся в квадратных скобках, элементы
индексируются с нуля, а каждая операция, «меняющая» массив, возвращает новый.

{{example:08-collections}}

Первые строки программы показывают встроенные действия массивов: `size()`,
`first()`, `last()`, `slice(start, end)`, `join(separator)` для массивов
строк, `ordering()` для сортировки и `item(index)` — или оператор индексации
`array[index]`. Индекс за пределами массива — отказ во время выполнения, если
только выражение не даёт запасного значения: `primes[9] else 0` — это `0`.
Как и у `slice` строк, ничего молча не подрезается.

Ещё пять встроенных действий ищут и меняют форму (тикет #211):
`contains(value)` и `index_of(value)` — `Maybe<int>` — сравнивают элементы
через `==`, так что объект-значение находится по своим полям; `reversed()`
разворачивает массив; `take(count)` и `drop(count)` оставляют, соответственно
убирают, не больше `count` элементов с начала. В отличие от `slice`, эти два
определены для любого неотрицательного числа — `[1, 2].take(5)` — это
`[1, 2]`, — потому что «не больше `count`» и обещают их имена; отрицательное
число — отказ.

Ещё два действия дают копию, изменённую в одном месте (тикеты #250, #251).
- `replaced(index, value)` — массив, в котором на месте `index` стоит `value`.
- `removed_at(index)` — массив без элемента с индексом `index`.

Исходный массив, как и везде, остаётся прежним. Индекс за пределами массива —
тот же отказ, что у индексации. `value` приводится к типу элементов по
правилам границы параметра: массив роли принимает её исполнителя, а `@any`
упаковывает значение. Других преобразований нет.

Диапазоны разворачиваются внутри литералов массивов: `[9, 0, 2..=4, 1]` — это
массив `9 0 2 3 4 1`. `a..b` исключает конец, `a..=b` включает его; границы —
целые, и начало не может превышать конец.

`ordering()` сортирует массив, элементы которого можно сравнивать. Он
сравнивает их через стандартную роль `Comparing` из модуля `compare`, поэтому
программа импортирует эту роль даже для сортировки чисел и строк, как в
примере. Без импорта компилятор его называет: «compares elements through the
role Comparing, which this program does not load: add
`import "compare" take Comparing;`» (тикет #233).

### Типовая идентичность

Массив помнит тип своих элементов. Как только он пересекает объявленную
границу — `let names is @string = ...`, параметр, поле, — он помечается этим
типом, и даже пустой результат `slice` или `keys` сохраняет его.
Нетипизированный пустой литерал `[]` не несёт свидетельств о типе, поэтому
может один раз пересечь любую совместимую границу, и эта граница фиксирует
его тип. Внутри большего выражения таким свидетельством служат соседи, на
любой глубине и в любом порядке: `[[1], []]` и `[[], [1]]` — это `@@int`,
`["a": [1], "b": []]` — `%string:@int`, а `[[1]] == [[]]` и
`if c { [[]]; } else { [[2]]; }` проходят проверку типов. Так заполняются
только части `never`. Два конкретных типа по-прежнему расходятся
(`[[1], ["s"]]`), а выражение, пустое на всю глубину, ждёт границы. Вот почему
пустым коллекциям иногда нужна аннотация (глава 4).

### Равенство

Массивы сравниваются глубоко: два массива равны, если у них одинаковая длина и
равные элементы в том же порядке. Словари сравниваются по ключам и значениям,
диапазоны — по границам и виду, объекты — по типу и *всем* полям. Сравнение
значений разных категорий — ошибка, а не `false`: то же правило, что для
`1 == 1.0` в главе 5.

## 8.2 Функциональные операции

Три операции — `map`, `filter` и `reduce` — работают с массивами,
диапазонами, словарями и любым объектом, исполняющим роль `Iterating`. Они
пишутся особым блочным синтаксисом:

```okkama
let squares = (1..=5).map() -> n { n * n; };
let odd = squares.filter() -> n { n % 2 == 1; };
let total = squares.reduce(0) -> sum, n { sum + n; };
```

Блок после `->` называет свои связывания и вычисляет одно значение. У
словаря `map` и `filter` связывают `key, value`, а `reduce` — `accumulator,
key, value`. Операции **энергичные**: каждая порождает полный массив (или, для
`filter` на словаре, словарь). Они обходят элементы по порядку — словари в
порядке отсортированных ключей — ровно один раз, и первый отказ внутри блока
останавливает операцию.

`map`, `filter` и `reduce` покрывают большинство циклов, вычисляющих значение. Их блоки — часть вызова: они могут использовать окружающие имена, но их нельзя сохранить или передать дальше. Ленивые представления — `Taken`, `Filtered`, `Chunked` и другие — находятся в `collections/views`, когда материализация каждого шага избыточна (глава 22).

Внутри функционального блока нет `last`: `reduce` всегда обходит каждый
элемент. Поэтому у поиска свои операции, которые останавливаются на первом
решающем элементе: `any` (есть ли такой?), `all` (все ли такие?) и `find`
(`Maybe` первого совпадения) — `xs.any() -> x { x.overdue(); }` там, где
иначе пришлось бы писать `reduce(false) -> found, x { found || x.overdue(); }`
и обходить весь массив (тикет #150). Поиску равного элемента блок вообще не
нужен: `xs.contains(y)`.

## 8.3 Словари

Словарь `%K:V` сопоставляет ключам значения. Литералы словарей пишутся в
квадратных скобках парами `ключ: значение`, и ключи — это *выражения*:
`["apple": 5]` сопоставляет строку `"apple"`; `[apple: 5]` использовал бы
значение переменной с именем `apple`. Неявной записи строковых ключей нет,
поэтому опечатка не может тихо превратить переменную в строку или наоборот.

Ключи — скалярные значения (целые, строки, булевы и другие скалярные
категории, кроме `byte` и `any`) или объекты-значения. Ключ `rat` — его
точное значение: `rat(1, 2)` и `2 / 4` — один ключ (с 0.4.2).
Объекты-значения — это объекты, все поля которых — скаляры, enum или такие же
объекты, без `destroy`. Объекты
неизменяемы, поэтому объект-ключ — это его поля: две равные карты — один
ключ, ровно как говорит `==`. Словарь хранит ключи **в отсортированном
порядке** — объекты по полям в порядке объявления. `keys()` и `values()` возвращают массивы в этом
порядке, и каждая функциональная операция обходит записи в нём. Поэтому
порядок обхода никогда не зависит от хэширования, истории вставок или
раскладки памяти конкретного запуска: одна и та же программа при каждом запуске печатает одно и то же. Python в версии 3.7 стал сохранять в
словарях порядок вставки по той же причине — предсказуемости, — а многие
наборы тестов в языках с неупорядоченными словарями содержат обходные пути
для недетерминированного вывода.

Поиск отсутствующего ключа — отказ во время выполнения, если нет запасного
значения: `stock["kiwi"] else 0`. `has(key)` спрашивает, не ища, а `Maybe` в
одном `if`, когда действие хочет вернуть отсутствие (глава 7).

Обобщённый объект может держать словарь, ключ которого — его собственный
параметр типа: `object Index<T> { has entries is %T:int; … }`. Такой `T` —
*ключевой параметр*, и компилятор требует от каждой специализации того же
правила ключей: `Index<string>` и `Index<Card>` компилируются, `Index<@int>` —
нет, как и `Wrap<U>`, который передаёт свой `U` в `Index<U>`, если дать ему
массив (тикет #242). Так устроены `KeyedSet<T>` и `KeyedFrequencies<T>`
стандартной библиотеки — логарифмические проверка членства и подсчёт, обход в
порядке ключей, — рядом с `OrderedSet` и `Frequencies`, которые принимают
любой `T` с равенством, включая массивы, и платят за это линейным поиском.

## 8.4 Диапазоны

Диапазон — значение: `1..5` и `1..=5` можно хранить, передавать и
сравнивать. Это источник большинства счётных циклов (`for 0..n -> i`), они
разворачиваются в литералах массивов и принимают функциональные операции,
порождая массивы. Цепочки вроде `1..5..9` отвергаются, а диапазон с началом
больше конца — ошибка, а не пустой диапазон: перевёрнутый диапазон чаще
ошибка, чем намерение.

## 8.5 Построение и изменение коллекций

Неизменяемость ставит практический вопрос: как построить коллекцию по
элементу или изменить одну запись словаря?

Ответ языка сегодня состоит из трёх частей.

1. **Строить за один шаг, когда возможно.** `map`, `filter` и развёртка
   диапазонов строят полные массивы за один проход. Большинство коллекций в
   реальных программах — преобразования других коллекций, и они линейны.
2. **Накапливать через `reduce` или библиотечную коллекцию.** В стандартной
   библиотеке есть персистентные коллекции — `List` (связный список с
   добавлением в начало за константу), `Deque`, `OrderedSet`, `KeyedSet`, `Heap`, — чьи
   «обновления» возвращают новые версии, разделяющие структуру со старыми.
3. **Перевязывать локальное имя, хранящее объект с преемниками.** Локальное
   имя можно перевязать (`counter = counter.increment();`), только если его
   тип — объект с successor-действиями; `let n = 1; n = 2;` отвергается.
   Скалярные и коллекционные локальные имена перевязать нельзя вовсе,
   поэтому накопление идёт через `reduce` или, в синхронном коде, через
   `cell::Cell` — единственный явный изменяемый контейнер, который компилятор
   не пускает в async-действия и поля объектов (тикет #152).

Используйте `+` и `-` для добавления элементов массива, установки и удаления записей карты: `items + [item]`, `a + b + c`, `prices + ["fig": 90]`, `prices - ["pear": 0]`. Цепочка конкатенаций стоит размера результата. Внутри `reduce` блок, возвращающий только `acc` или `acc + [item]`, добавляет элемент за амортизированное постоянное время; ранее наблюдаемые значения не меняются.

Одна идиома всё ещё копирует: она строит новый массив через `map` на каждом шаге. Её повторение для роста коллекции даёт квадратичную суммарную работу:

```okkama
let following = (0..old.size() + 1).map() -> index {
    if index < old.size() { old[index]; } else { item; }
};
```

Это самый ясный в языке пример правила из главы 1: убирая изменяемость,
нельзя убирать эффективность, и лекарство — операция, а не изменяемая
сущность.

## 8.6 Обход пользовательских коллекций

`for` обходит массивы, диапазоны, ключи словарей через `keys()` и любой
объект, исполняющий стандартную роль `Iterating<T>` из
`collections/iteration`:

```okkama
role Cursor<T> {
    available() is bool;
    item() is T;
    successor() is Cursor<T>;
}

role Iterating<T> {
    cursor() is Cursor<T>;
}
```

Курсор неизменяем: `successor()` возвращает следующий курсор и оставляет
текущий на месте, поэтому два цикла по одной коллекции не мешают друг другу, а
курсор можно сохранить, чтобы продолжить позже. Исчерпание — обычный `false`
из `available()`: ни метки, ни null, ни исключения. Роль номинальна:
коллекция должна объявить `does Iterating<T>`; подходящих имён методов
недостаточно.

Источник, который расходуется по мере чтения, — файл, сокет — вместо этого
исполняет роль `Batching<T>` из того же модуля:

```okkama
role Batching<T> {
    batch() is @T;      // следующая пачка; [] — источник кончился
}
```

`for file.text() -> line { … }` запрашивает порцию, обходит её как массив и запрашивает следующую. `next`, `last` и `return` работают как в любом цикле; `map`, `filter` и `reduce` тоже принимают такие источники. Порции распределяют стоимость запроса элементов между несколькими значениями. Источник, выполняющий обе роли, обходится порциями.

## 8.7 Количества и позиции: что происходит на краях

Действия массива принимают числа двух видов, и на краю массива они ведут себя
по-разному. **Количество** говорит «сколько»: просьба о большем, чем есть,
даёт то, что есть. **Позиция** называет элемент: позиция вне массива — отказ.

{{example:08-edges}}

| Действие | Аргумент | За концом | Отрицательный |
|---|---|---|---|
| `take(n)` | количество | весь массив | отказ |
| `drop(n)` | количество | `[]` | отказ |
| `slice(start, end)` | позиции | отказ | отказ; и при `start > end` тоже |
| `item(i)`, `xs[i]` | позиция | отказ; `xs[i] else v` даёт `v` | отказ; `xs[i] else v` даёт `v` |
| `replaced(i, v)`, `removed_at(i)` | позиция | отказ | отказ |
| `first()`, `last()` | — | отказ на пустом массиве | — |

Такой отказ — не брошенная ошибка, которую может поймать вызывающий, а сбой
времени выполнения, который останавливает программу с указанием места, как
деление на ноль (глава 10). `try? xs.slice(1, 9)` не превращает его в
`Maybe.none`. Асимметрия намеренная. Количество — это просьба, «не больше
трёх», и ответить на неё меньшим — полезный ответ. Позиция — это утверждение,
«элемент на пятом месте существует», а ложное утверждение — ошибка, которую
надо показать, а не значение, которое надо выдумать. Когда позиции законно
может не быть, программа говорит об этом через `else`.

## 8.8 Сортировка

`ordering()` возвращает массив, отсортированный по возрастанию, и это
единственная сортировка в языке. Она упорядочивает элементы через стандартную
роль `Comparing<T>` из `compare`, поэтому программа должна импортировать эту
роль даже для сортировки целых, а объект сортируется, когда реализует
`Comparing` (глава 14). Сортировка устойчивая: элементы, равные при
сравнении, сохраняют исходный порядок, так что сортировки по ключам одна за
другой складываются. Строки сортируются по кодовым точкам, как их сравнивает
`order()` (глава 6), поэтому `"B"` идёт раньше `"a"`.

Ни варианта по убыванию, ни сортировки по функции-ключу нет. Убывающий
порядок — это `xs.ordering().reversed()`, а сортировка по ключу — объект,
реализующий `Comparing` по этому ключу: маленький объект с именем вместо
анонимного компаратора. Это снова обмен бритвы: одна операция и одна роль
вместо семейства методов сортировки.

Программа ниже сортирует бегунов по времени, затем по клубу, затем от
медленных к быстрым и, наконец, по рейтингу, который знает не все клубы.

{{example:08-sorting}}

- **Ключ — это объект.** `ByTime` и `ByClub` оборачивают бегуна и
  сравнивают одно поле. Сортировка по ключу — три шага: обернуть,
  `ordering()`, развернуть. У обёртки есть имя, которого нет у анонимного
  компаратора, и это имя говорит, каков порядок.
- **Устойчивость складывается.** Bo и Cy пробежали за 39 минут, и сортировка
  по времени оставляет их в исходном порядке. Сортировка этого результата по
  клубу сохраняет порядок по времени внутри каждого клуба: в North Cy идёт
  раньше Ada. Чтобы отсортировать по нескольким ключам, сортируйте сначала
  по наименее значимому.
- **Разворот — не устойчивая сортировка по убыванию.** `reversed()`
  переворачивает весь массив, вместе с равными: «от медленных к быстрым»
  ставит Cy раньше Bo. Когда порядок равных элементов важен, убывающий ключ
  пишут отдельным объектом, чей `order` сравнивает в обратную сторону.
- **Сравнение может отказать, и сортировка останавливается.** `ByRank`
  бросает ошибку для клуба, у которого нет рейтинга, и первое такое
  сравнение заканчивает сортировку этой ошибкой. Наполовину отсортированного
  массива, который надо прибирать, нет: `ordering()` возвращает новый массив
  или отказывает, а `runners` остаётся каким был.

## 8.9 Разобранный пример: подсчёт слов

Словарей, `reduce` и `ordering()` хватает для классического упражнения —
подсчёта слов — без единого изменяемого счётчика.

{{example:08-words}}

`reduce` проводит словарь через слова. Каждый шаг возвращает словарь с одной
установленной записью: `seen + [word: n]` добавляет или заменяет запись, а
старый словарь остаётся прежним. Пустому словарю нужен объявленный тип
(`let empty is %string:int = [:];`), потому что `[:]` сам по себе ничего не
говорит о ключах и значениях (глава 4). Обход `counts.keys()` даёт слова в
отсортированном порядке, `and` раньше `the`, в каком бы порядке они ни
пришли, поэтому отчёт одинаков при каждом запуске и на каждой машине. Эта
детерминированность — свойство словаря, а не программы.

## 8.10 Разобранный пример: группировка и соединение

Отчёты — то место, где коллекции отрабатывают своё: строки приходят в одном
порядке, а их нужно сгруппировать, подсчитать и соединить с другими данными.
Вот пять продаж, сгруппированных по покупателю, а затем по городу и месяцу.

{{example:08-report}}

- **Группировка — это `reduce` в словарь массивов.** Каждый шаг ищет прежние
  продажи покупателя, `groups[sale.buyer()] else []`, и возвращает словарь,
  в котором эта запись заменена более длинным массивом. Запасное значение
  говорит, что значит первая продажа — пустую историю, — в единственном
  месте, где это важно. Ничего не мутирует: каждый шаг даёт новый словарь, а
  массивы в нём хранят продажи в порядке прихода.
- **Соединение — это поиск с запасным значением.**
  `cities[sale.buyer()] else "?"` соединяет каждую продажу с городом
  покупателя. У `cy` города нет, и программа решает здесь, в выражении, что
  такая продажа уходит в `"?"`. В SQL тот же вопрос — выбор между внутренним
  и внешним соединением; здесь это один `else` рядом с поиском, к которому
  он относится.
- **Составной ключ — value object.** У `Bucket` только скалярные поля,
  поэтому он может быть ключом словаря (раздел 8.3), и два bucket с одним
  городом и месяцем — один ключ. Словарь держит ключи упорядоченными поле за
  полем: сначала город, потом месяц. Строки сравниваются по кодовым точкам
  (раздел 4.7), поэтому `"?"` идёт раньше `"Lima"` и `"Oslo"`.
- **Вывод одинаков при каждом запуске.** Оба цикла идут по `keys()`, а они
  отсортированы, так что ни один отчёт не зависит ни от порядка входа, ни от
  хеширования. Перемешайте `sales` — программа напечатает те же восемь строк.

В SQL это `GROUP BY` и `JOIN`, а само соединение восходит к реляционной
модели Кодда [@codd1970]. Операции те же; программа добавляет к ним то, что
каждая — типизированное выражение, результат которого можно назвать,
протестировать и передать дальше.

## 8.11 Okkama среди других языков

| | Коллекции по умолчанию | Порядок обхода словаря | `map`, `filter` |
|---|---|---|---|
| Python | изменяемые `list` и `dict` | порядок вставки, гарантирован с 3.7 [@pystdtypes] | ленивые итераторы [@pyfunctions] |
| Java | изменяемые; `List.of` и `List.copyOf` дают неизменяемые списки [@javalist] | зависит от класса: не задан у `HashMap`, отсортирован у `TreeMap` | ленивые потоки [@javastream] |
| Go | изменяемые срезы и словари | не задан и не обязан совпадать от обхода к обходу [@gospec] | циклы |
| Rust | `Vec`, `HashMap`, меняются через `mut` | произвольный у `HashMap` [@rusthashmap], отсортированный у `BTreeMap` | ленивые итераторы [@klabnik2023] |
| Clojure | персистентные, неизменяемые, с общей структурой [@hickey2008] | неупорядоченный `hash-map`, упорядоченный `sorted-map` [@clojureds] | ленивые последовательности |
| Okkama | неизменяемые массивы и словари | всегда по ключу | энергичные; ленивые представления в `collections/views` |

Два столбца показывают выбор.

- **Порядок.** Дальше всех в обратную сторону идёт Go: спецификация ничего
  не обещает о порядке словаря, так что программа, которая от него
  зависит, неверна. Python выбрал порядок вставки. Okkama выбирает
  сортировку для каждого словаря, так что порядок следует из одних ключей:
  два словаря с одинаковыми записями обходятся одинаково, как бы их ни
  строили (раздел 8.3).
- **Ленивость.** В Python, Java, Rust и Clojure `map` и `filter` ленивы:
  ничего не выполняется, пока результат не потребуют, — это экономит работу
  на длинных конвейерах и делает момент отказа менее заметным. В Okkama
  они энергичны, так что отказ внутри блока случается на вызове, который
  его содержит. Когда ленивость окупается, программа просит её по имени,
  через представление (раздел 8.2).

Ближе всех Clojure. Её коллекции — неизменяемые значения, которые делят
структуру между версиями, как персистентные коллекции библиотеки Okkama
(раздел 8.5); разница в том, что в Okkama рядом нет изменяемой коллекции,
к которой можно отступить.

## 8.12 Ограничения

- **Что всё ещё копируется.** Идиома с `map()` и `a + b` двух больших массивов стоят полного результата.
- **Первое обновление большой карты стоит копии.** Последующие обновления могут быть дешевле; не считайте стоимость всех обновлений одинаковой.
- **`ordering()` требует `import "compare" take Comparing;`**, даже для
  чисел и строк; компилятор называет недостающий импорт (тикет #233).
