# C5: linear High builders

C5 is implemented in the High producer. This is structural implementation
coverage, not L05/L09 acceptance. All 143 `p2_3.tsv` rows remain `planned`;
#565 managed ownership audit, C6–C9, #593 and executable backend gates remain.
The C7 accumulator optimization is not enabled by this change.

## High forms and decisions

`builders.rs` uses synthetic environment slots for live buffers. Ordinary join,
branch and loop parameters carry those slots; they are internal context, not
language results, and therefore get no lexical want or D11 preparation.
Language collection results retain the existing preparation/result-exit rules.

- Arrays with at least eight parts and every range-expanded array use
  `builder.new`, ordered `push` / `append.range`, then `finish`.
- Scalar-only arrays with at least sixteen parts use bounded eight-element
  `array.new` groups and `builder.append`, without accumulating the entire
  literal's operands. The existing 65-element C4 golden now uses this path.
- Maps with at least eight entries stream ordered key/value evaluation and
  `mbuilder.new/put/finish`. Duplicate keys are not deduplicated by the producer.
- Concat/merge chains with at least eight operands use ordered
  `builder.append` / `mbuilder.append`, including existing concrete retags.
  Small literals and short persistent operators keep their existing forms.
- Exit paths and failure landing blocks use the matching `abandon` operation.
  Cleanup processes nested live buffers from inner to outer.

No user-facing builder API, packet/deps operands, `invoke.own`, new runtime
intrinsic or accumulator optimization is introduced. Buffer updates and finish
use the existing contracts. Collection operations synchronize failure state
only when their contract can fail/suspend, as scalar operations already do;
this avoids creating unreachable cleanup for non-failing observations.

## Plan §4.2 obligations

- [x] **Separate outcomes.** An update consumes the current buffer and yields
  its next version normally. Precommit unwind forwards the entry-visible input.
  `finish` has the same restoration behavior. Both buffer kinds are covered.
- [x] **H5 after update.** Before a subsequent failing argument/operation,
  split the block and carry the new version as an entry parameter. The previous
  operation keeps its old-input failure route. Changing the live set after
  finish also preserves the earlier operation's unwind.
- [x] **Exactly one abandon without finish.** Return, last/next out of the
  building expression, and failure paths abandon each exited buffer once.
  Buffers retained by a surrounding join/backedge or a catch inside the
  building expression continue under their forwarded SSA names. A builder
  started inside a try is abandoned before the failure reaches its catch.
- [x] **Outcome emitter boundary.** High names no restored edge results.
  Existing own/low `invoke.own` naming and packet materialization are unchanged;
  no file in `okkama-oir/src/own/` is modified.
- [x] **Independent element obligations.** Abandon releases only the buffer
  through the existing contract; High emits no element end, packet disposal or
  deletion of creation operands. Owner cleanup remains the responsibility of own.
- [x] **Overwrite history.** Every repeated `mbuilder.put` remains in order
  with its original key and value operands. `overwrite` contains two distinct
  resource constructors for the same key, followed by both puts.

## Scoped verifier ruling

Only `verify/linearity/packets.rs` changes in `verify/`. In `Engine::operation`,
`Profile::High` plus `Outcome::Unwind` plus `Rule::Buffer` selects exactly the
inputs named by the outcome contract's `Preserve` transfers. Those inputs are
checked as available borrows rather than consumed on that outcome. Their
unnamed restored slots are not populated as a second copy. Normal consumption
and all own/low paths keep their previous behavior. This implements the binding
§8 ruling without changing contracts or the SSA rules.

The former `oir2_c5_precommit_blocker` is now
`oir2_c5_precommit_preserves_input`, a positive regression. Canonical fixtures
under `okkama-oir/tests/fixtures/verify/` are:

| Class | Fixture | Expected rule and location |
|---|---|---|
| valid | `B81-high-precommit-push` | Normal abandons next; unwind abandons restored current |
| valid | `B81-high-precommit-put` | Same for mbuilder |
| valid | `B81-high-precommit-finish` | Successful finish vs restored builder abandon |
| valid | `B81-high-precommit-map-finish` | Successful finish vs restored mbuilder abandon |
| invalid | `B81-precommit-current-normal` | `OIR2-B8.1 instruction:0:4` |
| invalid | `B81-precommit-next-unwind` | `OIR2-B8.1 instruction:0:4` |
| invalid | `B81-precommit-lost-current` | `OIR2-B8.1 terminator:0:2` |
| invalid | `B81-precommit-own-unnamed` | `OIR2-B6.3 instruction:0:2` |

The `next` unwind negative names a result unavailable on that outcome. The
canonical harness checks rejection, named rule/location, codec round trip and
first/all diagnostic policies. These are High-visible IR errors (except the
explicit own-profile gate); no frontend builder syntax is invented.

## Goldens and verification

Fourteen source fixtures and stored goldens in `fixtures/p2_3/builders/` and
`goldens/p2_3/builders/`:

| Obligation | Golden |
|---|---|
| Carried buffer, branch, real loop backedge | `branch-loop` |
| Finish vs return abandon; first operand exits before any update | `early-exit`, `early-first` |
| Abandon on next/last while constructing | `loop-exits` |
| Failing later argument sees successful push's new buffer | `late-failure` |
| Nested live buffers, finish and unwind cleanup | `nested` |
| Repeated map key with two resource operands | `overwrite` |
| Streamed scalar literal and bounded append groups | `large`, `chunks` |
| `[9, 2..=4]` | `range` |
| Both append operation families | `array-append`, `map-append` |
| Outer buffer survives catch; inner buffer abandons before catch | `caught`, `try-abandon` |

Every golden is checked with `verify_high` before printing, after parsing and
from the stored expected text. Two independent lowerings and repeated printing
must match byte for byte. Fixtures are isolated and small; no #634 budget is
raised and no `Incomplete` result counts as success. The C4 `large-literal` and
`range-expansion` goldens are migrated to the new builder forms.
