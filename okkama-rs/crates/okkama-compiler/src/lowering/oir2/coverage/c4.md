## Implementation and decisions

- [x] Resolved THIR `BoundAction` lowers to `fn.bind receiver, @specialized-target, ty fn(...)`.
- [x] Resolved THIR `BoundRoleAction` lowers to `fn.bind.role receiver, role specialized-role,
      slot original-slot, ty fn(...)`. `Readable<int>` and `Readable<string>` have distinct declarations.
- [x] The receiver is evaluated once and the current SSA value is retained at creation.
      Rebinding the source binding never updates that snapshot. No mutable environment is introduced.
- [x] All snapshot packets are absent; target signatures retain the receiver prefix and concrete
      fn types exclude it. Ownership ABI stays Unelaborated and invocation operands use Borrow.
- [x] C3a's summary-free `fn.call` accepts finite lambda/method/exact-witness origins. Origins carry
      their entry-prefix length (lambda captures or one bound receiver), including mixed joins.
- [x] The producer admission proof follows callable fields through all immutable construction,
      successor-update and initialization inputs, and exact role calls through witness slots.
      Field facts conservatively union all instances of one specialized declaration.
      Unknown explicit entry inputs poison their entire nested object/role/variant field graph.
      An unused method's implicit receiver is sourced by the closed module's construction inventory;
      it is not an additional external object. Empty cycles and mixed known/open origins stay open.
      This is not an ownership proof or a registered open ABI; open calls remain Unsupported with O1.
- [x] Overloaded role slot names are uniquely printed as `read#slotN` only when overloaded.
      The declaration preserves THIR slot order and witness construction uses the original source
      method name and specialized parameter types. Bound selection never resolves again by name/arity.
      This fixes producer duplicate slot symbols without modifying the verifier.
- [x] Incomplete receiver checking occurs at the concrete bound method's entry before field reads.
      Exact role witness targets (and the underlying method of a result adapter) receive the same guard.
      Reference creation does not perform the check or claim invocation. Existing direct-call guards remain.
- [x] Frontend must-use analysis runs before receiver conversion. Pending successor receivers use
      `succ.take`, carried obligations survive binding/aliasing, and unused references remain rejected.
- [x] Role-bound successor results retain `fn() -> ^Counting`, `fn.call` produces `^Counting`,
      and later use emits `succ.take`; no `succ.erase` is introduced. Discarded results are frontend errors.
      Object successor methods remain excluded from bound-action selection by the existing frontend.
      The valid source form for this regression is the inferred role-bound successor signature;
      action-type syntax does not accept an explicit `() is ^T` boundary.
