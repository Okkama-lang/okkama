# C6: High traversal

This implements the binding C6 decision and plan §4.3 in the independent High
producer. It does not enable functional operations (C7), execute Okkama programs,
or establish L05/L09 acceptance. All 143 manifest statuses remain `planned`.
The thirteen C6 rows now link their structural evidence and remaining limitations.

## CFG and scope decisions

`iteration.rs` is a child module of `body.rs`, sharing the existing lexical
exit, binding, loop-frame and failure machinery. The former P1 range path and
std-only array path are replaced by the common indexed traversal. The std gate
is removed. The P1 range/scalar state layout and golden text are unchanged.
Specialization now visits Map, Iterating and Batching source expressions as well
as array/range operands, including their constructors and role coercions.
Ordinary variadic parameters now use the existing concrete `array<T>` signature
and THIR `Pack` boundary; traversing `Source::Varargs` reads that binding directly,
without materializing another array. Variadic role/native ABI remains Unsupported.
Implicit protocol calls require a reachable witness, just like explicit role
calls; an uncontracted open protocol remains an Unsupported diagnostic.

| Source | High CFG |
|---|---|
| Array / variadic array | `array.len → parent head(index,state) → Iteration(array.get,bind,body) → parent step(index+1) → head` |
| Literal range | Validate `range.new`; parent head compares the current integer with the inclusive/exclusive end; body binds that integer; parent step increments |
| Range value | `range.start/len`, exclusive upper bound; then the same indexed CFG |
| Resolved map | `map.len`, sorted integer positions, `map.value_at`, then the indexed CFG |
| Iterating | Bind source; `cursor()` once; parent enter → cursor-step scope(bind current,available) → child body(item,body) → cursor-step advance(successor) → parent enter |
| Batching | Parent refill → batch scope(batch(),bind batch,len) → empty/exhausted exit or inner indexed array loop; inner exhaustion exits batch scope to parent refill |

A cursor step has one entry, which binds the current cursor before `available`
and `item`. The body has its own child Iteration scope, so body locals retire
before `successor`. `next` leaves the body for the advance block; `successor`
is emitted there, inside the current cursor step. Its result and state receive
D11 preparation before crossing to the parent. That edge closes the old cursor.
Unconditional valued `last`, return and body failure have no reachable advance
block and emit no extra `successor`. Conditional exits likewise bypass advance
on their exiting edge. Protocol call failures keep the ordinary unwind route.

A batch is bound in its own Block scope, including the empty batch. All inner
backedges pass through that scope, the parent of the element Iteration. Refilling
exits the batch scope and re-enters its single entry through the enclosing
parent refill block; the next `batch()` runs after the previous scope exit.
`last` exits the entire traversal, while return and failure leave the batch and
iteration scopes through the existing exit/unwind machinery. No explicit own
cleanup operation, packet or hidden ownership protocol is emitted in High.

Batching/Iterating selection is taken directly from resolved THIR. The
`batch-preferred` fixture has both witnesses; its main contains exactly one
`batch` role-call site and no cursor calls.

## Boundaries and key objects (#635)

Direct `for map` is rejected by the current frontend; it only produces
`Source::Map` for Functional operations. `map-resolved-*` replaces the already
checked `m.values()` array source with its map receiver at the resolved THIR
boundary, binding its value side. This exercises sorted `map.value_at` traversal
without inventing or enabling source syntax. Ordinary `m.keys()` / `m.values()`
loops are covered end to end through frontend and High.

The #635 T1 ruling now permits structural key objects: no destroy, no attached
caps, no declaration cycle, and recursively key fields after substitution.
`fixtures/p2_3/traversal/map-object-key.ok` and its stored verified golden replace
`traversal-object-key-unsupported.ok` and the old blocker test. This is the original
`L05.map.object-key` source, including integer/rat fields and keys traversal.

Canonical verifier positives cover a plain key and nested generic keys (including
byte fields); negatives cover destroy, a cap field, recursive self-containment,
and an array substituted into a generic field. Every negative records its exact
T1 type location. `mbuilder.new` uses the same key check; the switch scalar rule
is preserved. No other verifier rule or ownership elaboration changes.

Functional map/filter/reduce/any/all/find remain Unsupported (C7). The two
Functional conformance rows owned by C6 in the initial inventory retain that
explicit C7 limitation. General builtin iterable adapters, ordering, plain once
plumbing, closures/any/caps and async work retain their existing boundaries.
Executable oracle/trace evidence and full conformance acceptance still require
#565, #569 where applicable, #593 and the executable backend. Claude review is
not performed by this change.
