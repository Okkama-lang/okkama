# C7: functional blocks in High

Implements the C7 decision and plan §4.4 in the independent High producer.
Every coverage status remains `planned`; executable L05/L09/ownership acceptance
still needs #565, #569 where applicable, #593 and the backend. No own change,
other verifier rule, frontend syntax, executable pipeline or intrinsic is added.

## CFG and lifetime decisions

- [x] All six THIR operations are CFG in the enclosing action. Arrow bindings
      are ordinary lexical bindings; nested blocks and outer names reuse the
      existing expression, return, failure and defer machinery.
- [x] C6 indexed/cursor/batch traversal is shared. Maps observe sorted positions
      through `map.key_at/value_at` and bind key then value. Source evaluation
      precedes init; opening the first cursor is part of source evaluation.
- [x] `map` publishes through `builder.push/finish` after the arrow body's own
      Block cleanup boundary. Fresh result parts get D11 preparations. If every
      body path returns/fails, the result type is array<never>: only its empty
      exhaustion state is carried, since no append or builder<never> is possible.
- [x] `filter` branches to insertion or skip; arrays/ranges/Iterating use an
      array builder, maps use `mbuilder.put`. Bound source items stay borrowed;
      no successor take or artificial fresh/temp intent grants ownership.
- [x] `reduce` carries its accumulator in a synthetic environment slot, hence
      in header/backedge parameters. The initializer is evaluated once, after
      the source (including cursor creation), even when input is empty.
- [x] `any/all` start with false/true and exit on true/false respectively.
      `find` uses the frontend's concrete Maybe none/some expressions. A decisive
      edge exits the traversal directly, bypassing body and cursor successor.
- [x] A result body leaves its Block boundary before builder mutation,
      accumulator replacement or decisive-result publication. Body resources
      and defers retire there; the enclosing Iteration closes on continuation.
- [x] Return exits the enclosing action and abandons active buffers. Failures
      keep the existing catch/unwind paths. An already wrapped buffer cleanup
      is preserved when catch arguments agree, avoiding obsolete cleanup blocks.
- [x] Batching uses an Iteration scope for functional traversal; no language
      result demand is invented for a linear builder crossing a batch boundary.
- [x] Anonymous action values inside arrow blocks remain Unsupported (#569).
      Frontend next/last restrictions are unchanged and checked negatively.
      Defer discovery enters functional bodies and excludes their own bindings
      from captures when an entire functional operation is deferred.

## Accumulator decision

In-place accumulator optimization is deliberately omitted. Both `reduce-append`
(the simple `acc + [x]` candidate) and `reduce-observable` (an alias observes acc)
retain persistent `array.concat`; tests require concat and forbid builder push
in those two cases. No equivalence/oracle claim is made for mutable accumulation.
The optimization row remains planned; a future implementation needs the strict
syntactic proof and executable oracle pair before replacing this behavior.
